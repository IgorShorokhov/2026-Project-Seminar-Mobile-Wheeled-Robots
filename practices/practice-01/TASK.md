# Практическая работа 1. Знакомство с ROS2

Познакомиться с окружением ROS2, топиками, сервисами и launch-файлами, а также с диагностикой работающей системы с помощью ROS2 CLI и `rqt_graph`.

## Подготовка

Практическая работа выполняется в подготовленном Docker контейнере, построенном на основе данного репозитория.

До практического занятия необходимо собрать и запустить Docker-контейнер с рабочим окружением курса. Для проверки его работы используйте примеры из репозитория курса и прилагаемые к ним инструкции по запуску. Убедитесь, что открываются графические приложения (`turtlesim`, `rqt_graph`) и стабильно работают.

## Задание

Создайте новый ROS-пакет, который рисует на экране число, соответствующее вашему номеру варианта (номер варианта определяется как ваш номер в списке) с использованием `turtlesim`.

### Начертание числа

Число должно быть отрисовано следующим образом:

1. Предполагается, что число включает два разряда (для однозначного числа используйте ведущий ноль: например, числу 7 соответствует начертание `07`).
2. Цифры необходимо отрисовать **набором прямых отрезков** (аналогично тому, как цифры отображаются семисегментными индикаторами).
3. Допускаются повторное прохождение отрезков и самопересечения.
4. Внутренние контуры и заливка не требуются. Толщина штриха, заливка и типографическая точность не оцениваются. Используйте максимально простое, но узнаваемое начертание.
5. Разместите цифры рядом, чтобы результат читался как одно число и помещался в окне `turtlesim`.

### Управляющая программа

Пакет должен содержать одну универсальную программу на языке Python (хотя допускается использование и C++) для управления **одной** черепахой. Для рисования числа запустите два экземпляра одной программы с различными параметрами (такими как: имя черепахи, рисуемая цифра и т.д.).

Каждый экземпляр управляет своей черепахой и рисует свою цифру. Реализовывать рисование всех десяти цифр не нужно, достаточно цифр вашего варианта.

Управляющая программа должна:

- Принимать параметры запуска (`<имя_черепахи>`, `<цифра>` и другие, при необходимости) средствами ROS2
- подписываться на топик `/<имя_черепахи>/pose` для получения текущего положения и ориентации;
- публиковать команды движения (линейную и угловую скорости) в топик `/<имя_черепахи>/cmd_vel`;
- использовать данные `pose` для определения момента завершения поворотов и прямолинейных движений;
- после завершения рисунка оставаться запущенным и публиковать нулевую линейную и угловую скорость.

Рисование должно выполняться за счёт движения черепахи по командам `cmd_vel`, без телепортации. Разрабатывать сложный контроллер не требуется.

### Запуск

Помимо управляющей программы ROS2 пакет должен содержать единый (и единcтвенный) `.launch.py` файл для запуска всей системы. При запуске необходимо:

1. Запустить `turtlesim`.
2. Удалить стандартную черепаху с помощью сервиса `/kill`.
3. Создать двух новых черепах с различными именами с помощью сервиса `/spawn`.
4. Запустить два экземпляра управляющей программы, настроенных на соответствующих черепах и цифры.

Сервисные вызовы могут выполняться вспомогательным узлом, который запускается тем же launch-файлом. Ручная подготовка сцены после запуска launch-файла не должна требоваться.

### Диагностика

В ходе работы попробуйте использовать инструменты командной строки ROS2 для просмотра запущенных узлов, доступных топиков и сервисов, а также сообщений в топиках.

После выполнения рисунка запустите `rqt_graph` и отобразите граф узлов и топиков. На графе должны быть видны оба управляющих узла и их связи с `turtlesim` через топики соответствующих черепах.

## Подсказки

1. В качестве примера при выполнении работы используйте предоставленный пакет `example_turtlesim`, изучите скрипты и launch файлы с запуском `turtlesim` и скриптов. Однако, для создания своего пакета рекомендуется использовать специальную команду. Подробнее об этом вы можете почитать [[обучающих материалах по ROS2](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Creating-Your-First-ROS2-Package.html)].

2. Цифру следует описать последовательностью простых действий: **повернуться до нужного угла -> проехать отрезок необходимой длины -> повернуться до следующего нужного угла -> проехать следующий отрезок**.
   - Сообщения в топике `pose` содержат текущие координаты $(x, y)$ и угол направления черепахи $\theta\;(\text{theta})$.
   - Перед началом очередного поворота определите, до какого абсолютного угла вам необходимо повернуться. Для поворота до нужного угла считывайте текущее значение $\theta$, затем задавайте постоянную угловую скорость при нулевой линейной. Когда угол окажется близко к нужному (в пределах некоторого небольшого диапазона), остановите поворот.  
   - Перед началом каждого прямолинейного движения запомните координаты черепахи $(x_{start}, y_{start})$. Затем задавайте постоянную линейную скорость при нулевой угловой скорости. По сообщениям `pose` вычисляйте расстояние от положения в начале отрезка до текущего положения:$$
dist = sqrt((x - x_{start})^2 + (y - y_{start})^2)$$
   Когда расстояние достигнет заданной длины, завершите движение и переходите к следующему действию. Не проверяйте точное равенство расстояния заданной длине: между соседними сообщениями черепаха может пройти дальше требуемой точки.
   - Таким образом, переход между действиями определяется положением черепахи, а не заранее подобранным временем движения.

## Что, как и когда сдавать?

### Код

1. Создайте собственный форк базового репозитория курса на свой аккаунт GitHub. Используйте один репозиторий для всех практических работ.
2. Для этой работы создайте отдельную ветку `practice-01` от исходной ветки `main`. Практические работы независимы, не создавайте ветку новой работы от веток предыдущих практик.
3. Разместите решение в папке `practices/practice-01`. Добавьте исходный код пакета, launch и остальные файлы, необходимые для сборки и запуска.
4. Создайте файл `README.md` в этой папке, укажите там инструкции по сборке и запуску.
5. Откройте `Pull request` из ветки `practice-01` в `main` **своего репозитория** (не используйте базовый репозиторий преподавателя). Запрос должен содержать изменения только по этой практической работе.
6. В заголовке запроса укажите `<ФИО, номер варианта>`.
7. Отправьте преподавателю ссылку на `Pull request` через форму сдачи. Не делайте merge веток до проверки вашей работы. Сохраните при этом ваш код до конца курса.

### Видеозапись

Запишите видео, на котором показаны:

- запуск решения с помощью launch-файла,
- весь процесс рисования обеих цифр и итоговый рисунок,
- граф узлов и топиков в `rqt_graph`.

Команда запуска и подписи на графе должны быть читаемы. Видео должно соответствовать сдаваемой версии кода. Видео должно быть без посторонних действий, пояснения не обязательны.

Загрузите видео в облачное хранилище, откройте доступ для просмотра по ссылке и добавьте ссылку в форму сдачи. Сохраняйте доступ к репозиторию и видео до проверки решения.

### Сроки и проверка

Для оценивания используется последний коммит в ветке на момент проверки. Для применения мягких дедлайнов учитывается дата этого коммита (либо дата отправки формы, если это произошло позже): если после дедлайна в ветку добавлены изменения, работа оценивается с соответствующим ограничением максимального балла.

Срок отправки:

- До основного дедлайна — максимальный балл без снижения.
- Не позднее 7 календарных дней после дедлайна — 75% от оценки.
- Позднее 7, но не позднее 14 календарных дней после дедлайна — 50% от оценки.
- Позднее 14 календарных дней после дедлайна — работа не учитывается в оценке за выполнение, если преподаватель заранее не объявил иной порядок.

Работа оценивается в представленном виде. Исправления и повторная проверка после выставления оценки не предусмотрены. Все сроки указаны по московскому времени (т.е. работа считается сданной, если она отправлена до 23:59 UTC+3 соответствующего дня дедлайна).
